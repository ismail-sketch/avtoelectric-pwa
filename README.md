# Помощник автоэлектрика

PWA для автоэлектрика-новичка: деревья диагностики по симптому, расчёты, журнал работ с фото. Работает офлайн, данные хранятся на устройстве.

## Что уже есть

- **Диагностика** — прохождение дерева шаг за шагом. «Норма / Не норма / Не знаю».
- **Встроенное дерево** «Не заводится» — 4 ветки (тишина / щёлкает / вяло / не схватывает), стоп-правила.
- **Расчёты** — падение напряжения, сечение и предохранитель, ток утечки, заряд АКБ по НРЦ.
- **Журнал** — машины, работы, фото (сжатие на входе), печать акта.
- **Дырки** — места, где в поле не знал, что делать. Копятся и дописываются дома.
- **Импорт деревьев из CSV**, проверка целостности, экспорт/импорт резервной копии.
- **PWA**: установка на телефон, офлайн, обновление по кнопке.

## Как добавить своё дерево

Дерево — это **данные**, не код. Пишешь в таблице, сохраняешь как CSV, импортируешь в приложении (Настройки → Импорт CSV).

Колонки:

| Колонка | Что писать |
|---|---|
| `id` | уникальный, латиницей: `a1`, `c3` |
| `type` | `question` / `check` / `outcome` |
| `text` | вопрос, что проверяем, или итог |
| `options` | только для question: `Да=>n1; Нет=>n2` |
| `tool` | чем проверять |
| `points` | точки подключения |
| `norm` | норма |
| `ifBad` | что делать, если не норма |
| `stop` | стоп-правило (показывается красным) |
| `next` | куда идти при норме (для check) |
| `badNext` | куда идти при «не норма» |
| `note` | примечание |

Стартовый узел — **первая строка** файла.

Шаблон можно скачать в приложении: Настройки → «Скачать шаблон CSV».

## Архитектура

```
src/
  domain/    чистая логика: типы, движок дерева, калькуляторы (+ тесты)
  data/      Dexie, репозитории, импорт/экспорт, сжатие фото
  content/   встроенные деревья
  screens/   экраны
  ui/        кнопки, карточки, поля
  state/     zustand: текущее прохождение и текущая машина
```

Правила, которых держимся:

- **Домен не знает про React и Dexie.** Движок дерева и калькуляторы — чистые функции.
- **UI не знает про Dexie.** Только через репозитории в `data/`.
- **Два независимых хранилища:** контент (деревья — можно переимпортировать) и пользовательские данные (журнал — терять нельзя).
- **UUID на клиенте + soft delete** (`deletedAt`) — чтобы позже можно было добавить синхронизацию без переписывания.
- **Схема БД версионируется** (`db.version(n).stores(...)`), контент версионируется отдельно (`TreeDoc.version`).
- **Фото сжимаются** до 1600 px по длинной стороне перед записью в IndexedDB.

## Ограничения

- Данные живут на одном устройстве. Перенос — через экспорт/импорт JSON.
- Синхронизации нет (осознанно). Нужна — отдельный этап.
- Расчёты ориентировочные: способ прокладки, температура и материал влияют на результат. Сверяйся с мануалом.
