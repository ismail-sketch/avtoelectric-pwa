## Что за проект

PWA «Помощник автоэлектрика»: деревья диагностики по симптому, расчёты, журнал работ с фото. Работает офлайн на телефоне, без бэкенда.

## Правила, которые нельзя нарушать

- **Домен не знает про React и Dexie.** Движок дерева и калькуляторы — чистые функции, покрыты тестами.
- **UI не знает про Dexie.** Только через репозитории в `data/`.
- **Контент отдельно от пользовательских данных.** Деревья можно переимпортировать, журнал терять нельзя.
- **UUID на клиенте + soft delete** (`deletedAt`) — задел под будущую синхронизацию.
- **Схема БД версионируется**: новая версия — `this.version(2).stores(...)` + миграция, не правка v1.
- **Фото сжимаются** до 1600 px по длинной стороне перед записью.
- **Офлайн обязателен.** Никаких сетевых запросов в рантайме, никакого бэкенда.
- **Синхронизации нет** — это осознанно, отдельный этап.

## Данные

IndexedDB `avtoelectric`, таблицы: `trees`, `cars`, `works`, `photos` (blob), `gaps`, `settings`.
Резервная копия — JSON через Настройки (фото в base64).

## Что уже работает

- Диагностика: дерево «Не заводится», 29 узлов, 4 ветки, стоп-правила. Кнопки «Норма / Не норма / Не знаю».
- «Не знаю» пишет дырку в отдельный список, чтобы дописать дома.
- Расчёты: падение напряжения, сечение + предохранитель, ток утечки, заряд АКБ по НРЦ.
- Журнал: машины, работы (путь по дереву сохраняется), фото до/после/дефект, печать через `window.print()`.
- Импорт деревьев из CSV с проверкой целостности (битые ссылки, дубли id, недостижимые узлы, циклы).
- Повторный импорт того же файла обновляет дерево и поднимает версию, а не плодит копии.
- Кодировка CSV определяется сама: UTF-8 и windows-1251 (старый Excel).
- Экспорт/импорт резервной копии, запрос `navigator.storage.persist()`.
- PWA: установка на телефон, офлайн, автообновление с тостом «Обновлено до версии N».

## Проверено

39 тестов зелёные. Вручную в браузере: полный проход дерева, сохранение работы, импорт CSV (включая кириллицу), экспорт копии, обновление service worker.

## Известные ограничения

- Одно устройство, без синхронизации.
- Приёмки авто и прайса пока нет.
- Редактора деревьев в приложении нет — только таблица + CSV.
- Акт печатается через системную печать, отдельного PDF-генератора нет.

## Следующие шаги (по приоритету)

1. **Приёмка авто** — фото кузова, пробег, «что не работало до ремонта», подпись.
2. **Прайс** — типовые работы, цены, время, история цен.
3. **Ещё деревья**: не работает свет, разряжается АКБ, стеклоподъёмник.
4. **Редактор деревьев** — формы в приложении поверх существующей модели.
5. Позже: синхронизация (PocketBase/Supabase), голосовые заметки.

## Как добавлять фичу

1. Модель и логика в `domain/` + тест.
2. Доступ к данным в `data/` (репозиторий, не прямой Dexie в экране).
3. Экран в `screens/`, UI-мелочи в `ui/`.
4. `npm test`, `npm run build`, коммит, пуш.
5. Для заметных изменений поднять `APP_VERSION` в `src/version.ts`.

## Осторожно

- Не ломать офлайн-режим и не добавлять сетевые запросы в рантайме.
- Не менять схему БД без новой версии и миграции.
- Не хранить фото в исходном размере.
- Не превращать приложение в «базу всех схем» — контент вводится CSV.
- Windows + PowerShell, путь с кириллицей и пробелами — всегда в кавычках.
- `gh` CLI не установлен; пуш работает через credential manager.
